# Guide to the `src` Subdirectories

This README explains each subdirectory inside `src/`. The directory contains several related research prototypes for applying classical and quantum linear-system solvers to power-flow and optimal-power-flow problems. The code is organized as a collection of experiments rather than as one installable Python package.

The main themes are:

- Fast Decoupled Load Flow (FDLS) solved with classical, HHL, and VQLS linear solvers.
- Recovery of the signs of HHL/VQLS solution amplitudes.
- Execution of HHL circuits through a QuApp workflow.
- Construction and solution of an SC-PDIPM KKT system for optimal power flow (OPF).
- Estimation of matrix condition numbers with a graph neural network (documentation snapshot only in this copy of `src`).

## Root FDLS experiment

The Python files directly under `src/` form the main Fast Decoupled Load Flow experiment.

### `main.py`

This is the primary entry point. It:

1. loads a reduced three-bus case derived from IEEE 14-bus data;
2. builds the bus-admittance matrix and the FDLS matrices `B'` and `B''`;
3. runs the same FDLS loop with three linear-system backends: NumPy's classical solver, HHL, and VQLS;
4. prints the first linear-system solution and the final power-flow results; and
5. writes convergence and voltage-comparison figures to `outputs/`.

Run it from this directory so its local imports and relative output path resolve correctly:

```bash
cd src
python main.py
```

### `config.py`

Central configuration for the root experiment. It controls the FDLS tolerance and iteration limit, HHL phase-estimation parameters, VQLS optimizer/ansatz settings, diagnostic printing, and the output directory.

### `ieee_case.py`

Defines the reduced three-bus network and utilities for building:

- the complex bus-admittance matrix `Ybus`;
- the decoupled matrices used in the active-power/angle and reactive-power/voltage steps;
- specified and calculated bus powers; and
- the initial voltage state.

Although the data is derived from IEEE 14-bus branches, this file intentionally uses only three buses for a small quantum-solvable demonstration.

### `fdls.py`

Implements the FDLS iteration. At every iteration it solves two linear systems with the selected backend:

```text
B'  Delta-theta = Delta-P / |V|
B'' Delta-V     = Delta-Q / |V|
```

The function returns convergence status, iteration history, voltages, calculated powers, and the first angle and magnitude corrections for comparison across solvers.

### `quantum_solvers.py`

Provides a common solver interface for:

- `classical_solve`: direct NumPy solution;
- `hhl_solve`: an HHL simulation using Qiskit statevectors; and
- `vqls_solve`: a variational quantum linear solver using a Pauli decomposition and classical optimization.

It also contains utilities for padding systems to a power-of-two dimension, cleaning numerical imaginary parts, estimating spectral bounds, and restoring the scale of normalized quantum solutions.

These implementations are research simulations, not hardware-optimized production solvers. The quantum methods can be substantially slower than the direct solver at the small matrix sizes used here.

### `plotting.py`

Creates the root experiment's loss-convergence, voltage-magnitude, and voltage-angle plots.

### `test.py`

An exploratory script that loads Pandapower's full IEEE 14-bus network, constructs a DC susceptance matrix, and starts assembling an OPF/KKT-style quadratic system. It is separate from the reduced-case FDLS workflow and is best treated as a research scratch/test script rather than an automated unit test.

## `fdls/`

This directory is a self-contained copy of the root FDLS experiment. It contains its own `main.py`, `config.py`, `ieee_case.py`, `fdls.py`, `quantum_solvers.py`, and `plotting.py`, plus an `outputs/` directory.

Use this copy when you want to run or modify the FDLS comparison in isolation:

```bash
cd src/fdls
python main.py
```

Because the root and `fdls/` files duplicate the same module names, make changes deliberately: editing one copy does not update the other.

### `fdls/outputs/`

Stores figures generated when the self-contained FDLS copy is run. In the current snapshot this directory may be empty.

### `fdls/__pycache__/`

Automatically generated Python bytecode. It is not source code and can be recreated by Python.

## `extract_sign/`

Quantum measurement normally gives amplitude probabilities and therefore loses direct information about the signs of real solution components. This directory experiments with methods for reconstructing signed HHL and VQLS solutions, especially parity/interference measurements and quantum state tomography.

Important top-level scripts include:

- `HHL.py`: standalone HHL implementation for a small Hermitian positive-definite system, followed by scale recovery.
- `Tomography_HHL.py`: HHL plus target-register quantum tomography and postselection utilities.
- `VQLS.py`: general VQLS prototype using automatic Qiskit Pauli decomposition.
- `Tomography_VQLS.py`: VQLS solution reconstruction using quantum tomography.
- `hhl_compare.py`: compares shot/postselection/sign detection with tomography on a 2-by-2 HHL example.
- `vqls_compare.py`: compares SWAP/parity sign recovery and tomography against a classical 4-by-4 solution; it can also redraw plots from saved results.

The PNG files beside these scripts are previously generated comparison figures.

### `extract_sign/compare/`

Contains refactored HHL/VQLS recovery modules and benchmark drivers for comparing sign-recovery approaches across small synthetic systems.

Key files:

- `hhl_shot_recovery_modules.py`: shot-based HHL recovery helpers.
- `hhl_tomography_modules.py`: tomography-based HHL recovery helpers.
- `vqls_two_modules_refactored.py`: VQLS recovery using the non-tomography method.
- `vqls_tomography_two_modules_refactored.py`: tomography-based VQLS recovery.
- `benchmark_hhl_recovery_methods.py` and `benchmark_vqls_recovery_methods.py`: benchmark and plotting entry points.

### `extract_sign/compare/benchmark_outputs/`

Generated benchmark artifacts. CSV files contain numerical results; PNG files compare errors and runtime; `systems/` contains saved NumPy `.npz` linear systems used by the benchmarks.

### `extract_sign/IEEE/`

Extends the HHL sign-recovery benchmarks to AC or DC power-flow systems derived from Pandapower IEEE cases. The versioned benchmark scripts represent successive experiment variants, including larger case sets, runtime comparisons, and Jensen-Shannon/relative-entropy dashboards.

Its `benchmark_outputs_*` directories are generated experiment snapshots:

- `benchmark_outputs_ieee_dc/`: baseline DC benchmark results.
- `benchmark_outputs_ieee_dc_js_dashboard/`: Jensen-Shannon dashboard results.
- `benchmark_outputs_ieee_dc_js_runtime_5cases/`: runtime and similarity results for five cases.
- `benchmark_outputs_ieee_dc_js_runtime_7cases/`: extended results for seven cases.

Within these directories, `systems/` stores prepared power-flow systems and `solutions/` stores recovered solution arrays. CSV and PNG files store summary metrics and plots.

### `extract_sign/output/` and `extract_sign/outputs_2x2_compare/`

Generated artifacts from the standalone VQLS 4-by-4 and HHL 2-by-2 comparison scripts. They include optimized/saved arrays, JSON summaries, convergence plots, signed-solution plots, and runtime comparisons.

### `extract_sign/__pycache__/` and `extract_sign/*/__pycache__/`

Automatically generated Python caches, not maintained source files.

## `hhl_quapp_workflow/`

This subproject separates HHL processing into deployable QuApp functions and a local orchestration/analysis layer. Its own `README.md` contains detailed deployment, API-token, input-schema, postselection, and sign-recovery instructions.

The workflow runs one main HHL measurement job to estimate squared amplitudes and multiple sign jobs to determine the relative signs between neighboring solution components. The local controller combines the results, restores the physical scale, compares with `numpy.linalg.solve`, and creates diagnostic plots.

### `hhl_quapp_workflow/quapp/`

Code intended for deployment as QuApp functions:

- `hhl-main/handler.py`: builds the main HHL circuit used to estimate solution probabilities.
- `hhl-sign/handler.py`: builds interference circuits used to recover relative signs.
- each function directory has its own `requirements.txt` for the hosted runtime.

### `hhl_quapp_workflow/local/`

Local orchestration and analysis tools:

- `run_workflow.py`: submits jobs, polls their status, saves JSON responses, reconstructs the signed solution, and creates plots.
- `analyze_saved_results.py`: repeats analysis and plotting from existing result JSON without submitting new quantum jobs.
- `analyze.py`: analysis utility for the checked-in result layout.
- `offline_smoke_test.py`: runs the deployed-handler logic locally with Qiskit Aer before deployment.
- `requirements.txt` and `requirements-dev.txt`: runtime and local-development dependencies.

The `input/` and `input_16x16/` directories contain saved QuApp job results used as analysis inputs. The `output/` and `output_16x16/` directories contain reconstructed summaries and figures for the corresponding system sizes.

### `hhl_quapp_workflow/samples/`

Example JSON payloads for the main and sign circuits, together with expected response schemas. These files are useful for validating integrations and understanding the API contract.

## `opf/`

Contains experiments that connect a security-constrained primal-dual interior-point method (SC-PDIPM) with VQLS for optimal power flow.

Key files:

- `scpdipm_kkt_case3sc_paper.py`: constructs a 16-by-16 KKT system for a three-bus security-constrained problem, applies left ILU preconditioning and spectral scaling, normalizes the right-hand side, and exposes the prepared matrices for VQLS.
- `vqls_scpdipm_case3sc_paper_complete.py`: imports that prepared KKT system, performs Pauli decomposition, optimizes a VQLS ansatz, recovers the SC-PDIPM search direction, and compares it with a classical reference.
- `load_case3.py`: an alternate/duplicated KKT preparation script for the same small case; verify which preparation module an experiment imports before editing it.
- `vqls_test.py`: a smaller exploratory VQLS test script.
- `scpdipm_case3sc_paper_matrix.npz`: saved KKT matrix/vector data.

### `opf/outputs_vqls_scpdipm_paper/`

Generated figures from the paper-style SC-PDIPM/VQLS comparison.

## `gnn_detect_conditional_number/`

This directory documents a graph-neural-network approach for estimating the 1-norm and 2-norm condition numbers of sparse symmetric positive-definite matrices. The documented design includes generated matrix families, graph/global features, GCN and MLP streams, training schemes, benchmarks, and matrix-size sweep experiments.

Important snapshot note: in the current `src` tree, this directory contains only its `README.md`. The package, configuration files, and artifact directories referenced by that README are not present here, so its training and prediction commands cannot be run from this copy alone.

## Generated and cache directories

### `outputs/`

## Dependencies

There is no single root `requirements.txt`, and different experiments need different dependency sets. Across the repository, the main packages are:

```text
numpy
scipy
matplotlib
qiskit
qiskit-aer       # shot-based simulation and offline smoke tests
pandas           # benchmark tables
pandapower       # IEEE power-network cases
requests
python-dotenv    # QuApp local controller
```

The GNN project documented under `gnn_detect_conditional_number/` additionally expects a PyTorch-based stack, but that implementation is not included in this snapshot. For the QuApp workflow, prefer the requirements files already provided inside its deployment and local directories.

## Suggested starting points

- To compare classical, HHL, and VQLS solvers inside FDLS: run `python main.py` from `src/`.
- To study how signed quantum solutions are reconstructed: start with `extract_sign/hhl_compare.py` or `extract_sign/vqls_compare.py`.
- To run or deploy the multi-job HHL workflow: read `hhl_quapp_workflow/README.md` first.
- To inspect the SC-PDIPM KKT-to-VQLS pipeline: start with `opf/scpdipm_kkt_case3sc_paper.py`, then `opf/vqls_scpdipm_case3sc_paper_complete.py`.
- To study condition-number prediction: read `gnn_detect_conditional_number/README.md` and obtain the missing implementation files before attempting its commands.

## Practical notes

- Run scripts from the directory that contains them because several imports and output paths are relative.
- Many scripts execute substantial work at module level; importing them may start calculations or print diagnostics.
- Quantum simulations with many shots, deep ansatzes, or large Pauli decompositions can be computationally expensive.
- Output directories contain experiment results, not reusable source modules.
- There are duplicated experimental files and versioned benchmark scripts. Keep a record of the exact entry point and parameters used when reproducing results.
